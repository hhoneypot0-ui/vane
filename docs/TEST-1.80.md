## 本轮修掉的缺陷

1. **整页长截图全黑 / 只有第一屏**（`MainActivity.captureLongScreenshot`）
   - 直画超长 Bitmap：硬件图层不参与软件绘制 → 全黑；
   - `View.scrollTo` 翻页无效（滚动在渲染进程）；
   - `window.scrollTo` + `View.draw` 仍只出第一帧；
   - 现方案：JS 滚动 → 等帧 → **PixelCopy** 抓窗口实际像素 → 按 `window.scrollY` 贴合，底部钳制时裁剪。
2. **保存密码弹两次**：表单 submit 与按钮 click 双触发，加 4 秒同内容去重。
3. **关于页写死「Vane 0.4.0」**：改为读 PackageManager 版本。
4. **云同步整体不可用**：`Prefs.get` 对 bool 键抛 `ClassCastException`（adblock 等），
   `Sync.buildPayload` 直接挂 → Prefs 取值改为类型容错；同步面板增加「上次结果」一行并落日志到 下载/Vane。
5. **导出（备份/书签/网址/主题包）在 Android 10+ 全部失败**：直写 /sdcard/Download 被分区存储拒绝，
   改走 MediaStore（下载/Vane）。
6. 云同步面板填一项就关闭 → 改为一律回到面板；恢复备份补上主题字段。

## 待继续

- 隐私空间视频加密播放 + 30s 回锁：入口是长按地址栏，解锁走系统锁屏验证，需要机主本人输入锁屏密码；
  代码路径（VaultFile AES-GCM 流式 → 解密到缓存 → FileProvider 播放，30 秒回锁在 VaultActivity）已复核。
- 恢复备份/导入：系统文件选择器（SAF）在本机只显示「最近」，选不到 下载/Vane 里的 json；
  需要换成分区存储友好的选择方式（或改成应用内文件浏览）。
- 主题切换与边缘手势：按钮可点，视觉差异需肉眼确认（读屏读不出配色）。

# 第二十三轮（1.85.3：主页按钮连点抖动）

## 现象（用户报）

连续点主页按钮，搜索框和地址栏反复跳转、页面抖动。

## 原因

`goHome()` 每次点击都 `t.load(ui.homePage)` —— 主页被反复重新加载：
搜索框重建、地址栏清空又聚焦、方块列表闪烁一次，所以看起来在「跳」。

## 改法

1. **500ms 防抖**：`lastHomeAt` 记时间，间隔内的重复点击直接 return。
2. **已经在主页就不重载**：只做三件事——重推方块（`pushHomeCards`）、重推引擎设置（`syncHomeEngine`）、平滑回顶。
   这样连点既不会白页，也不会闪。

| 在主页连点两次主页按钮 | 界面无变化（不再重载/抖动），方块与地址栏都保持原样 |

# 第二十六轮（1.85.9：页面泛紫修掉）

## 现象

用户反馈网页有紫色渲染。

## 原因

网页深色**上了两套**：
1. `BrowserTab.applyDarkening()` 打开 WebView 的**算法暗化**（Android 13+ 或 FORCE_DARK）；
2. `applyPageTheme()` 又注入我们自己的 `DARK_CSS`（压深背景、提亮文字）。

两套叠加等于二次处理颜色：深色主题里的蓝色链接被再反相一次就成了紫色，图片也跟着发紫。
（另外 `VideoSniffer.NIGHT_JS` 那套 `invert(1) hue-rotate(180deg)` 也是紫色来源，现在只留在阅读模式兜底。）

## 改法

`applyDarkening()` 改为**始终关闭**系统算法暗化，深色统一由 `DARK_CSS` 负责：

```java
WebSettingsCompat.setAlgorithmicDarkeningAllowed(web.getSettings(), false);
// 或 SDK<29 fallback: setForceDark(FORCE_DARK_OFF)
```

## 待确认

颜色只能肉眼看，读屏/截图看不清色偏；1.85.9 已构建安装，需要机主确认页面是否恢复正常色。
个别站点仍想强制不暗化，可在 设置 › 白名单域名（dark_skip）里加域名。

# 第二十七轮（1.86.0：深色主页边框变淡）

## 现象

用户截图：暗色主页的搜索框/方块边框看起来生硬发丑。

## 原因

`home.html` 深色变量给得偏亮：`--field:#303134`、`--line:#3c4043`，
搜索框聚焦时 `form:focus-within{border-color:var(--line)}` 就是一圈 1px 硬灰边；
再加上 WebView 的 `prefers-color-scheme` 不一定跟着 App 主题走，容易出现「App 是暗色、页面还是浅色边框」的错位。

## 改法

1. 深色变量压暗：`--field:#23252a`、`--line:#2a2d33`，搜索框底色 `#1c1e23`。
2. 聚焦不再用灰边：改成淡淡的强调色描边 + 3px 光晕
   `border-color:rgba(138,180,255,.55); box-shadow:0 0 0 3px rgba(138,180,255,.14)`。
3. 新增 `window.setDark(on)`，由 `engineJs()` 在载入/刷新时推送 `Theme.isDark()`，
   页面用 `html[data-dark="1"]` 走暗色变量，不再依赖 WebView 的媒体查询。

已装 1.86.0（关于Vane 显示 1.86.0）。

# 第二十九轮（1.86.2：下载页点不动）

## 现象

用户截图：Vane 内置「下载」页里点已完成的 APK 没有任何反应（只有 ✕ 能删）。

## 原因

`showDownloadsPage()` 生成的 HTML 里，每一行只有文本和一个删除链接：

```html
<div class=box>⤓ <div class=t>…</div> <a class=del href='vane://dl?op=del&id='>✕</a></div>
```

`div.t` 上没有 href、没有点击处理，`vane://dl` 也只认 `del / clear / dir / refresh`，
所以点条目 = 点了个死 div。

## 改法

1. 每一行的内容包成 `<a class=t href='vane://dl?op=open&n=<文件名>'>`。
2. `vane://dl` 新增 `op=open`：`openDownloadedFile(name)` 去 MediaStore（Downloads）按 DISPLAY_NAME 找到 uri，
   按扩展名给 MIME（apk → `application/vnd.android.package-archive`），带 `FLAG_GRANT_READ_URI_PERMISSION` 启动 ACTION_VIEW。
3. 找不到时提示「文件还没进媒体库，稍后再试或去下载目录」。

产物：`/sdcard/Download/DSH-Go/vane-1.86.2-arm64.apk`（已下载到手机，安装待补）。
